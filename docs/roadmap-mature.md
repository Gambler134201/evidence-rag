# 成熟 RAG 产品对标与迭代路线（2026-10-25 调研）

> 调研对象：GitHub 上以"产品"形态存在的成熟 RAG 项目（非框架）。目的：提取"成熟"的共性能力层，映射到本项目的迭代路线——**对标不等于抄功能清单**，每项吸收都要回答"这解决了我们评测/用户暴露的什么问题"。

## 2. 成熟产品的共性能力层

1. **引用溯源的"最后一公里"**：kotaemon 把引用直接高亮到浏览器内 PDF 原文上并附相关分数；RAGFlow 提供 chunk 可视化与人工修正。我们做到了"段落/页码定位 + 相对匹配度"，缺 PDF 原文高亮。
2. **混合检索 + 重排是标配**：kotaemon"hybrid (full-text & vector) retriever and re-ranking"；RAGFlow"multiple recall paired with fused re-ranking"。我们已完成一半（BM25+RRF 已实现），**重排（实验 C）是下一个正当实验**。
3. **低相关警告**：kotaemon 在检索相关度过低时显式警告用户。我们留了 `min_score` 配置位（待开发集校准），前端可低成本加警告条。
4. **分块的透明与可控**：RAGFlow 分块可视化 + 人工干预；我们的文档详情页已有"解析预览"，缺"重新分块/人工调整"操作。
5. **可观测性**：Dify 的执行轨迹；我们 query_runs 已存分段耗时/错误分类/引用快照，缺一个"轨迹查看页"。
6. **反馈与评估闭环**：反馈采集 → badcase 回流 → 回归评测。我们的闭环设计在 S4-T04，feedback 表已建，缺 UI 与流程。
7. **持续集成**：成熟项目人手一份 CI——我们 93 项测试目前只在本机跑。

## 3. 差距分析与取舍（吸收 / 缓做 / 不抄）

| 能力 | 我们现状 | 决策 | 理由 |
|---|---|---|---|
| 混合检索（BM25+RRF） | ✅ 已实现 | — | 首轮 A/B 未显优势，80 条冻结后加权编号题再验证 |
| 重排（实验 C） | 未实现 | **缓做** | 按规划"收益不足则不保留"；冻结集出数后再评估 |
| 低相关警告条 | 配置位已有 | **吸收（小）** | 前端一行警告，产品体验完整度大增 |
| 引用高亮到 PDF 原文 | 段落/页码定位已有 | **缓做** | 需字形级坐标解析，规划首期排除；MD 文档先做"锚点跳转" |
| 分块可视化+人工干预 | 解析预览已有 | **缓做** | 管理页已有预览，人工重分块等 S2-T06 复用迭代 |
| 查询轨迹查看页 | 数据已落库 | **吸收（中）** | 运行记录页是 backlog 既有项，顺势做 |
| 反馈闭环 UI | feedback 表已有 | **吸收（中）** | S4-T04 既定任务，提前到与运行记录页同批 |
| Prompt 版本化 | config_snapshot 已记录版本 | **部分吸收** | 已可追溯；不建独立 prompt 管理系统 |
| 多用户/成员管理界面 | 认证与权限已实现 | **缓做** | 核心引擎已完成，界面属 S2-T06 迭代 |
| CI 流水线 | 无 | **立即吸收** | 成熟开源的最低门槛，简历强信号 |
| GraphRAG / OCR / 连接器 / 多步 Agentic 检索 | 未实现 | **不抄** | 规划首期明确排除；除非真实用户问题出现（规划原话） |

## 4. 迭代路线（更新后）

- **阶段 3（当前，等作者复核 80 条草稿）**：冻结 40/40 → 正式 A/B（n≥3）→ 实验 C 重排按需评估 → badcase 回归（smk-07/10 已修）。
- **阶段 3.5 可信工程（新增，对标"成熟开源"底线）**：
  1. GitHub Actions CI：pgvector 服务容器 + 全量测试（本次已落地）；
  2. 运行记录页 + 低相关警告条；
  3. 反馈采集 UI 接入 feedback 表，打通 badcase 回流。
- **阶段 4 产品化（M4/M5 并行）**：用户验证、PDF 锚点跳转、多用户管理界面、流式输出（校验后流式，契约允许）。
- **明确不抄**：GraphRAG、OCR、网页连接器、多模态解析、多步 Agentic 检索——除非真实用户问题或评测结果证明需要（原规划 §3 原话，这也是与"功能清单式产品"拉开差距的地方）。
