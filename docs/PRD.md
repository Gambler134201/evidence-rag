# PRD v0.1（S0-T02）

编制：2026-10-24（ZCode/GLM 会话，范围依据原规划，未新增未确认承诺）。状态：待验收。

## 1. 目标用户与场景

| 用户 | 要解决什么 |
|---|---|
| 查阅文档的成员 | 快速得到"当前有效规则"的答案，并能点开引用核对原文；资料没有时明确知道"没有" |
| 维护文档的管理员 | 上传/更新/停用文档有状态反馈；失败可见可重试；版本切换不出半套索引 |

首期场景：团队项目交付知识库——需求发布、阶段交付、验收期限、退回整改、争议处理、操作说明。

## 2. 四类页面与核心状态（原规划 §4 固化）

1. **问答页**（已实现骨架 `apps/web/`）：回答区（带引用角标）、证据列表（文档/版本/定位/相似度）、状态徽章六态：answered / insufficient_evidence（证据不足，已拒答）/ needs_clarification / conflicting_evidence / knowledge_changed / error（服务故障，区别于"无答案"）。
2. **知识库页**（未实现，S2-T06）：文档列表、版本、索引进度、失败原因。
3. **文档详情页**（未实现，S2-T06）：段落/页码定位、版本、生效状态、解析预览。
4. **评测与运行记录页**（未实现，S1-T09 数据已落库）：先表格化，不建复杂后台。

## 4. 产品取舍记录（case study 素材）

| 背景 | 备选 | 选择 | 理由 | 影响 |
|---|---|---|---|---|
| 引用编号由谁生成 | 模型自由输出文档 ID / 模型只给局部编号 C1..Cn，服务器补全真实来源 | 后者 | 模型编造 ID 无法程序拦截；局部编号可用"编号 ⊆ 本次证据集合"机械校验 | 前端引用展示由服务器载荷驱动；模型提示词必须给编号化证据 |
| 无答案的形式 | 一律拒答 / 先澄清再拒答 | 先澄清（needs_clarification），证据确认缺失才拒答 | 问含糊 ≠ 资料没有；混用会虚增拒答率并误伤可回答问题 | 基线暴露 smk-10 G2 badcase（该澄清没澄清），回流素材 |

## 5. 历史回答与撤权保留策略（S2-T04 测试依据）

- 撤权/停用后：新查询、原文、历史运行详情、导出立即按新权限判断（404）；**系统无法撤回用户已读或已保存的内容**（文档明示，不做撤回承诺）。
- 仍有权限时：旧版本引用可打开，显著标注"历史版本，已不适用于新查询"。
- 首期不做跨用户回答缓存。
