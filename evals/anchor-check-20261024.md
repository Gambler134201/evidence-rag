## 1. 方法与局限

### 1.1 检查项（对应任务口径 a–g）

| 项 | 内容 | 判定输出 |
|---|---|---|
| a | version_id 是否在语料元数据中存在；kb/document_id/版本命名与 supersedes 链是否机械自洽；与 caller.kb 的关系 | 有效/无效 + 备注 |
| b | anchor 条款编号是否在该版本文档正文命中（章节标题为强命中，仅行内提及为弱命中） | 命中/弱命中/未命中 |
| c | gold text 与条款原文一致性：先 NFKC 全半角+去空白（保留标点）找精确子串，再全半角+空白+标点全归一找精确子串；都找不到按字符二元组重合度近似 | exact / paraphrase / mismatch |
| d | must_not_include 短语是否真实存在于语料（含否定语境识别、近似变体滑窗提示） | 命中/未命中（行为约束类）/未命中（需作者确认） |
| e | smk-09：用 `datetime` 独立验算 2026-10-16 星期与 3 个工作日序列，并与 A-F-02 原文、required_info_points 交叉核对 | 通过/不一致 |
| f | smk-03：A-D1-01 适用日期范围 vs 题面提交日期 vs 元数据 effective_at/valid_until vs as_of | 通过/不一致 |
| g | type/expected_status 组合与 `badcase-taxonomy.md` 第 2 节口径表对照（含 notes 与口径表的矛盾检测） | 一致/表外类型/冲突 |

### 1.2 归一化与分级定义

- **exact**：gold text 经归一化后是条款原文的精确子串（两级归一化任一命中即可，报告中注明所用级别）。
- **paraphrase**：精确子串未命中，但整篇字符二元组重合度 ≥ 55%（机器启发式，仅代表字面相近，不代表语义正确）。
- **mismatch**：精确子串未命中且重合度低于阈值。
- 归一化：`unicodedata.normalize('NFKC')`（全角→半角）、小写、去除全部空白；第二级再去掉全部标点/符号。
- 工作日验算仅按周一至周五（与语料演示口径一致，不含法定节假日与调休）。

### 1.3 局限（机器检查做不了什么）

1. 无法判断语义等价与业务正确性：exact 只证明字面一致，不证明『这句话作为金标语义上正确』。
2. required_info_points 的事实支持未逐条机器验证（仅 smk-09 的日期类信息点做了验算）。
3. must_not_include 中的行为约束类短语（『任何百分比』等）无法机器验证，只能标注为行为约束。
4. 权限/越权（smk-05）与注入抵抗（smk-08）只能验证语料文字存在，**不能验证系统真实行为**；notes 中『mock 通过不等于真实模型已抵抗』的约束机器无法替代。
5. paraphrase 的重合度阈值是经验值，可能漏判或误判。
6. 口径对照使用的 type→expected_status 惯例是机器推断（见脚本内 `STATUS_CONVENTION`），不是口径文件原文。
